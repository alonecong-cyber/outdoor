# OutdoorDeal PRD — 户外服饰比价与最低到手价

> 来源：《户外服饰比价与最低到手价项目 · 研发计划》。本文件是开发执行的唯一依据。

## 1. 定位

帮户外服饰买家回答一个问题：**这件衣服（这个颜色、这个尺码），现在在哪买、用哪几张券叠加、最终到手多少钱，比历史价是不是真便宜。**

- 核心用户：买始祖鸟、TNF、Patagonia、猛犸象、萨洛蒙、凯乐石等中高端户外服饰的国内消费者，客单价高、对优惠敏感。
- 次要用户：海淘党，需要在"国内大促到手价"与"美国折扣 + 返现 + 转运 + 关税"之间做选择。
- 差异点：现有工具多是"单平台标价/券后价"，我们算的是**同款同尺码的跨渠道最终到手价**，含海淘落地成本。

## 2. MVP 范围

| MVP 做 | MVP 不做 |
| --- | --- |
| 品牌 3 个：始祖鸟、TNF、Patagonia | 得物、闲鱼等二手/潮牌平台（无公开 API，风控严） |
| 款式 30–50 个核心款，细到颜色 × 尺码 | 全站爬取、多用户账号体系 |
| 国内：京东联盟、淘宝联盟、品牌中国官网 | 小程序、浏览器插件（第二阶段） |
| 海外：AvantLink 上的 REI / Backcountry 等 | 自动下单、自动领券 |
| 价格历史 + 30/90 天新低 | 多商品跨店凑单的 ILP 全自动求解（第二阶段做 CP-SAT） |
| 降价、补货、券快过期提醒（Telegram / 邮件 / 企业微信） | |
| 单品最低到手价 + 海淘落地价计算器 | |

## 3. 数据来源与合规

| 优先级 | 来源 | 能拿到什么 | 注意 |
| --- | --- | --- | --- |
| 1 | 京东联盟 `jd.union.open.goods.query` | 商品、价格、券列表（面额、门槛、有效期） | 需 app_key；按 SKU 批量查需权限 |
| 1 | 淘宝联盟 `taobao.tbk.dg.material.optional` | 券后价、券面额、是否天猫/海外 | 需备案淘宝客应用 + PID |
| 1 | AvantLink ProductSearch | 美国户外零售商 SKU、原价、折扣价 | 3600 次/小时、15000 次/天 |
| 1 | Rakuten / CJ / Impact | 商品目录与价格 | 始祖鸟官方计划在 CJ |
| 2 | 品牌中国/美国官网单品页 | 官方价、尺码库存、会员价 | 只监控指定单品页；robots.txt，≥10 秒/请求 |
| 3 | 人工/线报（什么值得买、Slickdeals、大促规则页） | 跨店满减、平台券、信用卡活动 | 大促期间人工录入，最可靠 |
| 不做 | 天猫/京东/得物网页批量爬取 | — | 反爬严，有不正当竞争判例 |

**合规底线**：不绕过登录、验证码和风控；不大规模复制、转售平台数据；不实质替代平台服务。联盟 API 是官方给比价导购的合法通道。

## 4. 系统架构

```
数据源 → 调度器(APScheduler, 按优先级定频)
       → 采集器 jd / tbk / avantlink / web_product → RawListing
       → SKU 归一化（款号+型号+颜色+尺码匹配）
       → 存储（SQLite→Postgres：快照、优惠、匹配关系）
       → 优惠规则引擎（券/满减/返利/税费）
       → 最低到手价求解（枚举 + 背包 DP + CP-SAT）
       → 到手价触发提醒（通知）
FastAPI（查询/计算/提醒接口） → 前端
```

| 模块 | 职责 | 关键设计 |
| --- | --- | --- |
| 采集器 | 各渠道数据 → 统一 `RawListing` | 解析顺序 API → JSON-LD → CSS；失败退避，不绕风控 |
| SKU 归一化 | 确认不同网站上是不是同一件、同一色、同一码 | 规则优先（款号正则+词典），相似度兜底，<0.85 转人工 |
| 存储 | 价格快照、优惠规则、匹配关系 | 只在变化时写快照；价格存"分"为整数 |
| 规则引擎 | 把优惠表达成可计算的结构 | 类型、门槛、上限、作用范围、互斥组、计算顺序 |
| 求解器 | 算最低到手价并给出逐步明细 | 单品枚举；凑单用背包 DP；多商品多渠道用 CP-SAT |
| 通知 | 按到手价触发提醒 | 同类提醒 24 小时去重；历史少于 14 天不报新低 |

## 5. 最低价组合算法

1. **优惠建模**：`type`、`threshold`、`amount/rate`、`cap` 上限、`scope` 作用范围、`exclusive_with` 互斥、`apply_order` 顺序（直降/会员价 → 店铺券 → 店铺满减 → 跨店满减 → 平台券/红包 → 支付立减 → 返利）。
2. **单品单渠道：枚举**。单渠道可用优惠通常 ≤12 个，2^12=4096 种子集，过滤互斥组合后按顺序计算取最低，返回每一步明细。
3. **凑单：0-1 背包 DP**。满 N 减 M 差一点时，从关注清单/低价凑单品里找"刚好超过门槛、多花最少"的组合，按金额（分）做 DP。
4. **多商品多渠道：CP-SAT 整数规划**（M6）。`x[商品,渠道]∈{0,1}`、`y[优惠]∈{0,1}`；约束：每件只买一次、y=1 时订单金额 ≥ 门槛、互斥组 Σy≤1；目标最小化总到手价。
5. **海淘落地成本**：汇率每日更新；行邮税税额 ≤50 元免征，单次限值 2000 元，超限提示可能退运。

公式：

- 国内到手价 = 标价 − 直降 − 店铺券 − 满减分摊 − 平台券 − 支付立减 − 返利
- 海淘到手价 = (美元价 × (1−折扣) × (1−折扣码) + 美国运费) × 汇率 + 转运费 + 行邮税 − 返现×汇率

返利/返现按实付金额计算、事后到账，与"当下实付"分开展示。满减分摊按商品金额比例摊到每件，退货才算得准。

**海淘试算验收样例**（测试必须精确复现）：
输入：$450，折扣 25%，折扣码 10%，返现 8%，美国运费 $0，汇率 7.1，转运费 ¥220，行邮税 20%。
输出：商品实付 $303.75 → 商品+运费折人民币 ¥2156.63 → 行邮税 ¥431.33 → 转运 ¥220 → 返现折回 −¥172.53 → **最终到手 ¥2635.42**；商品价值超 2000 元单次限值，提示可能退运/按货物报关。

## 6. 技术选型

| 层 | 选型 | 理由（Intel Mac、无 Docker） |
| --- | --- | --- |
| 语言/环境 | Python 3.12 + uv | uv 装依赖快，不用 Docker |
| 采集 | httpx + Playwright(Python)（可选 extra） | 能静态取就不开浏览器 |
| 后端 | FastAPI + SQLModel + pydantic | 类型清晰，AI 生成代码质量高 |
| 数据库 | SQLite → Postgres（Homebrew） | 零运维；迁移用 Alembic |
| 调度 | APScheduler（SQLite job store） | 单进程即可，重启不丢任务 |
| 求解 | OR-Tools CP-SAT / 纯 Python 枚举 | 免费、性能好、pip 直接装 |
| 前端 | Next.js + Tailwind + React Query | 移动优先；后期可换 uni-app |
| 通知 | Telegram Bot、SMTP、企业微信机器人 | 官方 webhook，接入简单 |
| 常驻 | launchd（本地）/ systemd（云） | 不依赖容器 |

## 7. 里程碑

| 阶段 | 周期 | 交付物 | 验收 |
| --- | --- | --- | --- |
| M0 准备 | 第 1 周 | 联盟账号申请；PRD + 数据模型；项目骨架 | `/health` 可用；联盟账号提交审核 |

| M3 到手价 | 第 5–6 周 | 规则引擎 + 单品枚举 + 海淘落地价 | 20 个真实订单误差 ≤1 元 |
| M4 历史与提醒 | 第 7 周 | 快照、新低判定、TG/邮件/企微 | 一周无重复提醒、无漏报 |
| M5 前端 | 第 8–9 周 | 首页、商品页、计算器、提醒设置 | 手机上能完整走通 |
| M6 扩展 | 第 10–12 周 | CP-SAT 多商品凑单、AvantLink 海外、更多品牌、插件/小程序 | 按需排期 |

一人 + AI 助手，每周 10–15 小时，MVP（M0–M5）约 9 周。

## 8. 风险与应对

| 风险 | 等级 | 应对 |
| --- | --- | --- |
| 联盟 API 权限申请不下来 | 高 | 先用关键词查询；个人申请不了找第三方 CPS 服务商代理接口 |
| 大促规则复杂、变化快 | 高 | 规则做成可配置 + 人工录入，不追求全自动解析活动页 |
| SKU 匹配错误导致比错价 | 中 | 低置信度转人工；页面显示匹配依据；允许用户反馈 |
| 官网改版或反爬 | 中 | JSON-LD 优先；失败告警；不绕风控，失效降级为人工 |
| 海淘政策和转运渠道变化 | 中 | 转运费和税率做成配置，标注更新日期 |
| 法律合规 | 中 | 只用官方接口和公开单品页低频监控；不转售数据；保留 robots 记录 |
